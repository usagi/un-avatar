# UNPhysics / UNDynamics v2 Design

UNPhysics は、UNAvatar が扱う avatar physics 全体の製品・設計上の総称とする。
v2 の実装対象は、その中の bone dynamics layer である UNDynamics に限定する。

## Naming

- `UNPhysics`: avatar physics 全体の umbrella。bone dynamics、contacts、constraints、将来の cloth / soft body などを含められる名前。
- `UNDynamics`: v2 で実装する source-neutral runtime layer。VRM SpringBone と VRC PhysBone を authored intent として読み取り、UNPhysics 独自の runtime terms へ lower する。
- `UNEvaluation`: wardrobe / action / animation / parameter / contact 由来の runtime state を評価する層。module 名は `runtime_eval`。詳細は [`unevaluation-v2.md`](unevaluation-v2.md)。
- `SpringBone`: VRM / UniVRM 由来の source format または既存実装資産を指す名前に限定する。
- `PhysBone`: VRC component 由来の source format を指す名前に限定する。

Solver / renderer / wardrobe runtime の public boundary では、可能な限り `UNDynamics` の語彙を使う。
`SpringBoneSimulator` など既存名は互換 shim として段階的に残してよいが、新しい behavior を SpringBone 固有 API に直接足さない。
SpringBone / PhysBone を v2 physics model の基準にはしない。v1 solver と source component は実装・入力資産であり、UNDynamics runtime model の設計基準ではない。
Profile / manifest schema では `[physics.dynamics]` を UNPhysics / UNDynamics の正本境界にし、solver backend 調整は `[physics.dynamics.solver]` に置く。旧 `[physics.spring_bone]` は v1 / 開発中 profile の読み込み互換であり、新規保存先にはしない。
旧 root key `spring_bones` は v1 互換の残骸として読み捨てる。UNPhysics の有効/無効は `[physics.dynamics].enabled` だけを正本とし、`spring_bones = false` だけで v2.1 dynamics を無効化してはならない。

## Design Boundary

VRM SpringBone、VRC PhysBone、VRC PhysBone Collider、VRC Contacts、VRC Constraints は source metadata として保存できる。
ただし runtime solver は source component の忠実再現を目標にせず、正規化済み UNDynamics model を読む。
UNPhysics の目標は source 互換そのものではなく、authoring intent を失わずに、安定し、自然で、ユーザーが調整しやすい独自の物理挙動を実現することとする。

UNDynamics の中核概念:

- `UnaDynamicsGroup`: stable source id、enabled state、source provenance、solver parameters、chains、writeback mode、colliders、limits、interactions を束ねる runtime group。
- `UnaDynamicsChain`: 親から子へ向かう node chain。PhysBone endpointPosition は synthetic endpoint chain node として lower できる。
- `UnaDynamicsCollider`: sphere / capsule / inside bounds など source-neutral collider。
- `UnaDynamicsLimit`: angle / stretch など chain motion constraints。angle cone は現 solver backend が扱える拘束として近似反映し、stretch は tail simulation の許容長として扱う。安全な translation writeback target がある場合だけ、伸びた tail 距離を実 node の local translation へも書き戻す。
- `UnaDynamicsInteraction`: grabbing / posing など interaction capability metadata。v2 初期は runtime action / diagnostics のために保持する。
- `UnaDynamicsContact`: VRC Contacts を source-neutral event / proximity metadata として保持する。
- `UnaDynamicsConstraintRef`: VRC Constraints や Modular Avatar resolver が残す参照関係を、bone dynamics rebuild / reset の判断材料として保持する。v2 初期では solver 入力ではないが、global dynamics reset 対象 node には含める。runtime action / wardrobe による source-scoped enable 切替では、対象 source group の dynamic nodes と重なる constraint ref だけを reset 対象に含める。CLI diagnose / renderer runtime status / Supervisor diagnostics は VRC constraint ref が metadata/reset ref only であることを warning として出す。

既存 v1 の tail integration / collider code は実装資産として再利用する。
ただし v2.1 の設計上は、SpringBone solver に PhysBone feature を直接追加するのではなく、UNDynamics が出す runtime terms を source-neutral solver backend が解く、と扱う。
UNDynamics は解く対象を定義する層であり、group / chain / collider / force / drag / pull / limit / interaction / contact / constraint intent を source-neutral に持つ。
Solver backend は解き方を定義する層であり、Verlet、PBD / XPBD 的な拘束解法、反復回数、安定化、衝突解決順などのアルゴリズムを持つ。
このため v2 初期で v1 solver 由来の backend を使っても、PhysBone source を SpringBone source へ変換したとは呼ばない。未対応 term は source metadata / normalized metadata / diagnostics に残し、SpringBone semantics へ丸めたことにしない。

## UNPhysics Response Model

UNPhysics / UNDynamics は SpringBone / PhysBone の数値再現ではなく、両 source が表す authored intent を読み取って独自の response model へ写す。
この response model は部位や source に依存しない共通語彙を持ち、UI、manifest、diagnostics、solver tests は同じ語彙で説明する。

Runtime terms:

- `rest_response`: rest pose へ戻る速さ。source の復元 intent と profile の復元力をここへ集約する。部位名だけで暗黙に値を変えず、必要な特殊性は template / recommended preset / match override で明示する。
- `inertia`: 親や頭が動いたときに tail particle がどれだけ置いていかれるか。source の drag / immobile / motion coupling 由来の intent を反映するが、親が動いただけで折れたまま戻らない挙動は regression とする。
- `bounce`: 揺れ返しと余韻。source の Spring / Momentum 由来 intent を受けるが、数値上の完全一致は狙わず、過発振と硬直を避ける。Solver では damping で失われる慣性の一部を保持する term として扱い、final `bounce_response` は solver 実効範囲の 0..1 に収める。実効 inertia retention が 1 を超えてエネルギーを増幅する状態は regression とする。
- `damping`: 残留運動の消え方。UI では half-life として扱い、source drag は authored default の材料にする。
- `gravity_bias`: rest direction から重力方向へ寄せる量。Gravity Falloff は重力方向と chain rest direction の関係を滑らかに変えるための shape term として扱う。
- `motion_coupling`: parent / center / world motion をどれだけ dynamics state へ移すか。Immobile / ImmobileType はここへ lower し、source 固有の内部式ではなく UNPhysics の追従/置き去り量として解釈する。
- `shape_preservation`: 前フレームの局所的な曲がり方や chain のまとまりを保つ補助項。これは rest pose へ戻す力ではなく、`rest_response` とは独立した局所形状保持である。値を上げると形は保つが、髪や布では板状の硬さを生むため、診断では `pull` と分けて観測する。
- `constraint`: length、angle、hinge、polar、stretch、collider、inside bounds などの最終拘束。source の limit は拘束 intent として保持し、solver backend が表現できる範囲で反映する。

Tuning semantics:

- 「柔らかさ」は `rest_response` だけで表現しない。髪、布、耳、尾、小物、soft body は、`rest_response`、`shape_preservation`、`motion_coupling`、`damping`、`bounce` の組み合わせで揺れ方が決まる。
- `rest_response` は 0..1 の authored intent / UI intent であり、solver では指数応答へ変換する。値そのものを 60fps の 1 フレーム復元率として使わない。低から中程度の値は髪、布、長い耳を柔らかくできる調整域として残し、高い値だけが短い chain を素早く戻す。
- Soft preset は、低い `rest_response`、低い `shape_preservation`、低から中程度の `motion_coupling`、長めの damping half-life、必要な bounce を同時に設定する。`rest_response` だけを下げて `shape_preservation` や `motion_coupling` が高いまま残る状態は、見た目に硬いままなので regression とする。
- Firm / snappy preset は、単に硬くするのではなく、過剰な余韻を減らし、復元を速くし、必要な形状保持だけを増やす。短い耳や小物では破綻防止のため `shape_preservation` を残してよいが、長い髪や布へ同じ値を適用してはならない。
- Profile / match / group override は final response として扱う。source scalar、source curve、chain length shaping は、明示 override を再スケールしてはならない。stretch / squish も同じ方針で、`stretch_range_scale` は source-authored range を倍率補正し、`stretch_motion` は range の参加率を final response として上書きする。

Solver policy:

- Solver は fixed-step の tail particle integration を基本にする。render FPS、motion input FPS、wardrobe transition によって見た目が大きく変わらないことを優先する。
- Source kind は import / lowering / diagnostics の情報であり、frame loop の分岐軸にしない。solver は normalized terms と profile overrides だけを読む。
- XPBD compliance は UNPhysics の追加拘束 softness であり、source parameter の代替ではない。profile preset は `rest_response`、`bounce`、`damping` も同時に動かし、compliance だけで「柔らかさ」を表現しない。
- XPBD backend では、明示 profile `rest_response` から暗黙 compliance を導出し、明示 `xpbd_compliance` がある場合でもその値を softness floor として扱う。これにより XPBD でも UI の復元力調整が実際の constraint softness に届く。source-authored compliance 相当値は、profile `rest_response` override が無い場合だけ既定値として使う。
- `rest_response=0` 付近でははっきり柔らかくなり、`rest_response` を上げると短い chain が自然にピコピコ戻る。UI の復元力が効かない状態は regression とする。
- Solver の復元 gain は、低い `rest_response` と低い `motion_coupling` を持つ chain が rest target から外れた場合だけ、変位量に応じて非線形に少し強くする。短い chain は局所変位が大きい場合だけ対象にし、長い chain は tip 全体の遅れが各 segment へ分散するため、chain 長に応じて小さめの分散変位にも回復下限を持たせる。小さな揺れや、既に高い復元/追従を持つ chain には適用しない。これは長い tail / hair / cable が置き去りのまま残る状態を避ける安全弁であり、部位名やモデル名による隠れ補正ではない。
- Angle / polar limit がある chain では、重力で曲げた rest target を limit 内へ射影してから `rest_response` を計算する。制限外の target へ毎フレーム引っ張り、直後に constraint で戻す実装は定常入力や履歴依存の静止解を作るため不可とする。
- Polar limit は authored local X / Z axes を区別する。`maxAngleX` は limit rotation 適用後の local X 方向の傾き、`maxAngleZ` は local Z 方向の傾きを拘束する。X/Z を入れ替えると、横方向と前後方向で可動域が異なる cloth / hair / accessory で意図しない軸が狭まり、片側だけ接着されたように見えるため regression とする。
- Wardrobe asset group に所有される dynamics は、現在 active な asset group に属する source だけを solver 対象にする。Modular Avatar Merge Armature 後に別衣装の PhysBone が同じ runtime bone path へ lower される場合、非表示衣装側の dynamics を残すと複数 solver が同じ骨へ書き込み、布やアクセサリが固着したように見える。未所有 dynamics は既存互換のため常駐扱いにする。
- VRC PhysBone root は root 自身を最初の可動 joint として扱う。runtime chain では root の親を anchor として prepend し、`parent -> root -> child...` を solver へ渡す。root を anchor として扱うと、root bone に weight された布やアクセサリが固定され、子の一部だけが動くため regression とする。scene root に親が無い場合は従来通り root 起点にする。
- Source scalar / per-joint curve sample は authored intent の入力であり、profile override より強い最終値ではない。solver へ渡す直前に joint ごとの UNPhysics response を解決し、明示 profile override は source sample の有無に関わらず必ず final response へ反映する。`rest_response` は sample 付き joint の `pull` を上書きし、`shape_preservation` は sample 付き joint の局所形状保持を上書きする。`bounce_scale` は group scalar だけでなく `spring` / `momentum` sample にも掛かり、最終的な `bounce_response` は solver 実効範囲の 0..1 に clamp する。旧 profile の `stiffness_hz` は `rest_response` の読み込み互換 alias として扱う。`damping_half_life_ms` は時間基準の安定化減衰、source Drag と `drag_scale` は作者由来の減衰として独立に保持し、残存率を乗算して final damping response を作る。一方を指定したことで他方を捨てない。`motion_coupling` は親/center motion を dynamics state へ持ち込む量として `immobile` 由来の既定値を上書きする。
- Solver runtime の joint state は `rest_response` / `shape_preservation` / `bounce_response` を正本 term として保持する。`pull` / `stiffness` / `spring` は source-authored input、legacy alias、public diagnostics 互換名に限定し、最終 solver response の内部名にはしない。
- Profile の category override mode を `override_verlet` / `override_xpbd` へ切り替えるときは、単に solver だけを切り替えない。カテゴリは template selection のヒントとして使い、natural UNPhysics preset を明示 override として seed する。`rest_response` / `shape_preservation` / `motion_coupling` / `damping_half_life_ms` / `bounce_scale` / XPBD softness を一貫して初期化することで、「override にしたが source drag や bounce だけが残って硬い」状態を避ける。旧互換名 `stiffness_hz` は読み込み alias としてのみ扱い、保存 manifest と Supervisor UI setting payload は `rest_response` / `rest_response_configured` / `authored_rest_response` を正本名にする。
- `immobile` / `immobileType` は PhysBone 内部式の再現ではなく、UNPhysics の `motion_coupling` 既定値へ lower する。`0` でも完全な置き去りではなく部分追従を基準にし、`AllMotion` の `immobile` が高いほど剛体追従寄り、`World` は局所的な頭/親 motion の揺れを残す。
- `center_node` は source-specific な特別挙動ではなく UNPhysics motion frame として lower する。center がある group は center frame の delta を `parent_motion_follow` の基準にし、center が無い group は従来通り child / rest target frame を基準にする。これにより root/world motion と chain root の局所 motion を分け、center が固定されている状態で chain root だけ動いた場合は揺れとして残せる。
- Solver 内部の姿勢保持項は `shape_preservation` として扱い、source の Stiffness をそのまま追加の復元力にはしない。明示 profile `rest_response` は source pull sample より優先され、明示 profile `shape_preservation` は source stiffness sample より優先される。これにより「戻る速さ」と「形を保つ硬さ」を別々に調整できない状態を regression とする。
- Renderer runtime status / Supervisor diagnostics / CLI diagnose は response category summary と source-id group summary の両方で `rest` / `shape` / `bounce` / `stretch` / `squish` / `stretchMotion` / `damp` / `follow` / `orient` を出す。`shape` は局所姿勢保持の強さ、`stretch` / `squish` は solver 直前の effective length range、`stretchMotion` はその range の参加率、`damp` は明示 `damping_half_life_ms` がある場合の平均半減時間、`orient` は実際に orientation response へ入る `shape_preservation * parent_motion_follow` の平均である。`rest` を下げても硬い場合は、まず group summary で対象 source id の `shape` と `orient` が高すぎないかを見る。stretch source があるのに伸縮しない場合は、`stretch` / `squish` が残っていて `stretchMotion` が 0 になっていないかを見る。JSON には既存 tooling 互換のため `average_pull` / `average_stiffness` / `average_spring` alias も残すが、新規表示と調査では `average_rest_response` / `average_shape_preservation` / `average_bounce_response` / `average_max_stretch_response` / `average_max_squish_response` / `average_stretch_motion_response` / `average_damping_half_life_ms` を使う。長い chain の root-to-tip 分布を観測するため、`rest` / `shape` / `bounce` / `stretch` / `squish` / `stretchMotion` / `follow` は average だけでなく min/max も出す。
- Long hair / cloth / tail は単発の復元力だけでなく inertia、bounce、damping の組み合わせで自然さを作る。bounce は damping を無効化する追加加速ではなく、減衰した慣性の保持量を調整する。短い chain 用の硬さを長い chain へそのまま適用しない。
- Source scalar だけで per-joint curve が無い長い chain では、root から tip へ向けて response を分布させる。root 付近は少し形を保ち、tip 付近は `rest_response` / `shape_preservation` / `motion_coupling` を下げ、`bounce_response` を少し残す。これは cloth / hair / tail が板や棒のように動く状態を避けるための UNPhysics fallback である。source authored curve がある joint と profile の明示 override は既に author / user の final intent を持つため、この自動 joint-position shaping では再スケールしない。
- `gravity_bias` は外力として毎フレーム加算するのではなく、rest target の方向と、stretch constraint が許す範囲の target length を変える response term として扱う。`rest_response=0` なら gravity-biased target へ勝手に移動しない。

Category and template policy:

カテゴリは diagnostics、UI grouping、recommended preset、match override seed のためのヒントであり、solver core はカテゴリ名だけで物理 response を暗黙に変えない。同じ source-authored Pull / Stiffness / Spring / Momentum を持つ group は、カテゴリ名が `hair` でも `cloth` でも同じ基礎 response から始める。

Source-authored Pull / Stiffness / Spring / Momentum / Immobile は final response ではなく、source-neutral UNPhysics response へ変換する。明示 profile override は final response として扱い、この source scaling を受けない。
Category classification は source `category`、comment、source id の leaf component 名、chain node names を優先し、それでも決まらない場合だけ full source path を fallback に使う。親階層の `skirt` / `cape` などが leaf component の `watch` / `bag` / `hat` などを上書きしてはならない。名前情報が不足した汎用 `Bone` chain を位置だけで `ears` などへ分類しない。必要なら diagnostics から match override を seed する。
Default category aliases should cover common outfit authoring names where the source component already carries semantic intent. For example, `shirt` / `sweater` / `dress` / `coat` / `longcoat` / `frill` / `stocking` style roots are cloth, while `bag` / `bookbag` / `earring` / `shoe` / `footwear` / `watch` / `brooch` / `hat` / `tie` / `necklace` / `potion` / `bottle` / `cable` / `strings` style roots are accessory. `breast` / `butt` / `cheek` style body jiggle roots are `soft_body`. This keeps fallback response shaping source-neutral without adding model-specific path rules. Alias matching normalizes separators and camel-case authoring names into semantic tokens, accepts numeric suffixes such as `Hair1`, and chooses the longest matching semantic alias so `earring` remains accessory instead of matching the shorter animal-ear alias `ear`. It should not classify unrelated words by substring accidents such as `chair` -> `hair` or `gear` -> `ear`.
`[[physics.dynamics.solver.group_overrides]]` は source id 完全一致で特定 group の final response を上書きする。適用順は category override と ordered match override の後であり、source id override がカテゴリ既定や名前ベース調整より優先される。これにより、名前やカテゴリ推論では安全に分類できない group でも、source payload を失わずに UNPhysics response へ直接接続できる。source id は CLI diagnose / renderer runtime status / Supervisor diagnostics の group summary に出る値を正本とする。

User-defined matching policy:

- Built-in categories and aliases are fallback templates, not the final customization boundary. They should make common assets usable out of the box, but users must be able to define their own matching rules.
- Profile / Supervisor exposes an ordered list of user-defined dynamics match rules. A rule can match by exact source id, normalized source/comment/chain token contains array, and regular expression. Existing compact entries such as `longcoat` still match adjacent tokens such as `long_coat`, but single-token substring accidents such as `ear` matching `earring` are not considered matches. Matching rules produce the same final response terms as category / group overrides: `rest_response`, `shape_preservation`, `motion_coupling`, `damping`, `bounce`, `stretch_range_scale`, `stretch_motion`, solver backend, XPBD softness, and iterations.
- Supervisor category previews use the same token boundary matcher for source id, comment, and chain node names. This keeps UI suggestions aligned with renderer/runtime matching and avoids preview-only substring accidents such as `chair` becoming hair or `earring` becoming animal ears.
- Built-in templates are UI seeds for user-defined `match_overrides`; they are not automatic runtime rules. A template affects rendering only after the user adds it to the ordered rule list, where it follows the same merge order as any other match override.
- `[[physics.dynamics.solver.match_overrides]]` is the general ordered matching mechanism. `source_id` is exact, `source_id_contains` is an array of normalized token contains matches against source id / comment / chain node names with adjacent-token compact matching kept for existing profiles, and `source_id_regex` is an array of regular expressions checked against the same match text. Multiple matching rules merge in order; exact `group_overrides` still run last as a final pin.
- Runtime diagnostics expose matched rule names on each response group. Invalid regular expressions are reported in diagnostics instead of being indistinguishable from a non-match.
- Supervisor diagnostics can seed a `match_overrides` entry from a dynamics group when the group has a useful semantic name. Generic chain names such as `bone` are intentionally ignored to avoid broad accidental matches. If no useful semantic name is available, diagnostics may seed an exact `match_overrides.source_id` rule instead; this remains an ordered match rule and is not the same as the final `group_overrides` pin.
- Exact `group_overrides` remain available as a manual final per-source-id pin after inspecting a specific model. They are not the default diagnostics seed path.

```toml
[[physics.dynamics.solver.match_overrides]]
name = "soft skirt and cape parts"
source_id_contains = ["skirt", "cape"]
rest_response = 0.04
shape_preservation = 0.02
motion_coupling = 0.28
damping_half_life_ms = 180
bounce_scale = 0.65

[[physics.dynamics.solver.match_overrides]]
name = "soft hanging straps"
source_id_regex = ["(?i)strap.*tail|ribbon.*tail"]
rest_response = 0.08
shape_preservation = 0.04
motion_coupling = 0.45
```

Chain length response:

source-authored intent には chain 長と joint 位置に応じた一般補正を掛ける。これは長い chain を短い chain と同じ硬さで解くと板状・棒状になりやすいためである。補正対象は source-authored `pull` / `stiffness` / `spring` / `immobile` 由来の既定 response だけであり、profile の明示 `rest_response` / `shape_preservation` / `motion_coupling` / `bounce_scale` は final response として扱うため chain 長で再補正しない。

- 3 joints 以上で rest / shape / motion coupling を段階的に下げ、長い chain の慣性を残す。
- root から tip へ向かって rest / shape / motion coupling を下げ、bounce を少し残す。
- `rest_response` の長鎖補正は「棒状化を避ける softness」と「入力停止後に自然な静止姿勢へ戻れる recovery floor」の両方を満たす。長鎖だからといって source-authored pull を過度に減衰させ、布や尾が baseline から大きく外れた静止解へ固着する状態は regression とする。
- `immobile` から motion coupling への変換は非線形にし、中間値で硬くなりすぎず、1.0 では親 motion を強く抑える。

Validation policy:

- 代表モデルは `usagi`、`mizuki`、`blanca` を使う。usagi は ears / wardrobe cloth / multiple wardrobe、mizuki は hair / skirt / large PhysBone group、blanca は material/texture regression とあわせて確認する。
- Fixture は source 値の再現ではなく、response property を測る。例: profile の復元力を下げると max lag が増える、damping half-life を下げると余韻が短くなる、cloth が腕/肩 motion へ自然に反応する、group override が source sample より後段で final response に届く。
- 目視確認は必要だが、最終的には runtime status と solver unit tests で「UI 変更が normalized terms と solver output に届く」ことを固定する。

## Source Data And Runtime State

Source data:

- `.unavatar` / glTF extension の `dynamics[]` は authored source payload と provenance を保持する。
- VRM SpringBone の authored values、VRC PhysBone の component fields、PhysBone Collider、Contacts、Constraints 参照は失わない。
- asset group ownership、source node id、component path は source package data に属する。
- VRC PhysBone 由来データの解釈根拠は、VRChat Creator Docs、Unity Inspector / SerializedProperty で見える公開フィールド、ユーザー所有 project / `.unavatar` に含まれる authored data、黒箱観測に限定する。VRChat SDK / client の内部実装、逆コンパイル、逆アセンブル、source code derivation は設計・実装根拠にしない。UNPhysics は PhysBone の内部挙動再現を目標にしない。

Runtime state:

- active wardrobe set、active asset groups、runtime action parameter、dynamics enabled override は runtime state に属する。
- `dynamicsEnable` は authored default を書き換えず、stable dynamics id に対する runtime override として扱う。Renderer runtime control の `set_dynamics_enabled` command も同じ runtime override 経路を使い、`sourceId` / `enabled` で個別 group を切り替える。Supervisor diagnostics の group toggle もこの command を使い、source data や authored default は変更しない。Renderer tray の UNPhysics toggle は現在の wardrobe scope に対する runtime operation として扱う。
- solver state は source scene を直接 mutate せず、resolved scene / pose buffer / runtime dynamics view から構築する。
- runtime state の owner policy と continuous evaluator は UNEvaluation が扱う。UNDynamics solver は評価済み enabled state / parameters / colliders を読むだけで、wardrobe / action / contact の優先順位を決めない。
- UNMotion `signals` は UNEvaluation の animation-linked parameter input として扱い、宣言済み action / ModularAvatarParameters runtime parameter だけを更新する。UNDynamics group の enabled state はその parameter 変化から既存 runtime action evaluator を通って更新される。PhysBone interaction suffix は direct interaction evaluator 実装まで値を書かない。

Stretch / writeback policy:

- Stretch は source-specific PhysBone feature ではなく、UNDynamics chain limit と solver writeback の能力として扱う。
- 現 solver backend は tail position を解いた後、ボーン local transform へ rotation を書き戻す。stretch limit がある joint は tail 距離を `max_stretch` 上限まで許容する。`writeback_mode: rotation_translation` で、かつ安全な target がある joint だけ、伸びた tail 距離を next chain node または 2-node endpoint child の local translation へも書き戻す。
- stretch writeback 対象は skinned joint ではない実ノードに限定する。multi-node chain は next chain node、2-node endpoint chain は終端 child node 自身を対象にできる。Humanoid / skinned deformation の基準ボーンには既定で translation stretch を書かず、solver は scene skin joint set を見て skinned joint child を translation writeback candidate から除外する。CLI diagnose / renderer runtime status / Supervisor diagnostics は group ごとの `translation_writeback_candidate_count` / `translation_writeback_target_count` と全体の `dynamics_rotation_translation_writeback_group_count` / `dynamics_translation_writeback_candidate_count` / `dynamics_translation_writeback_target_count` / `dynamics_stretch_translation_writeback_target_group_count` を公開する。
- `max_stretch` は rest tail length に対する上限倍率、`max_squish` は下限倍率、`stretch_motion` はその伸縮 range の参加率として正規化する。値は solver simulation の許容長に使い、gravity-biased target もこの範囲を超えない。writeback mode が `rotation_only` の group、または target の無い skinned chain では node translation は維持し、tail simulation の伸縮感だけに反映する。Unity Exporter は PhysBone の `maxStretch` / `maxSquish` / `stretchMotion` または対応 curve が authored されている場合、`.unavatar` dynamics entry へ `writebackMode: "rotation_translation"` を付けて source intent を渡す。`maxStretchCurve` / `maxSquishCurve` / `stretchMotionCurve` は base scalar の倍率として chain tail ごとに sample し、joint ごとの実効 length range へ反映する。`maxAngleXCurve` / `maxAngleZCurve` は base angle の倍率として chain tail ごとに sample し、source-neutral な `max_angle_x_samples` / `max_angle_z_samples` として joint ごとの実効 cone / polar constraint へ反映する。
- 非常に大きい `max_stretch` と正の `stretch_motion` は source authored intent として保持し、値そのものを非対応や規約違反扱いにはしない。ただし chain rest length に対する lag や局所 translation writeback が大きく出やすいため、CLI diagnose は effective enabled group に限って large stretch range warning を出し、source id、root path、effective `max_stretch`、effective `stretch_motion` を bounded sample として表示する。これは VRChat SDK の内部挙動を再現した判定ではなく、UNDynamics/UNPhysics solver 上の数値監査である。
- SpringBone 的な固定長拘束を単に緩めるだけの実装は不可とする。現 solver backend は joint ごとの tail particle と local transform 書き戻し対象が一段ずれる箇所を持つため、particle / writeback target map を明示して扱う。solver は multi-node chain の next chain node だけを current tail writeback target とし、multi-node 末端や 2-node leaf chain の imaginary tail を実 node へ二重割当しない。

Lowering:

- VRM SpringBone source は UNDynamics group / chain / collider / parameter view へ lower する。
- VRC PhysBone source も同じ UNDynamics view へ lower する。source-specific fields は `sourceParams` と normalized metadata の両方で保持してよい。
- VRC PhysBone authored default は source の `enabled` を尊重する。明示 `enabled:false` の group は authored default disabled として lower し、wardrobe / action / Supervisor profile opt-in で runtime override できる。CLI diagnose / renderer runtime status は runtime dynamics group が存在するのに effective enabled group が 0 の場合、物理が source として保存されていても現在の runtime state では solver 対象が無いことを warning として出す。
Source importer は authored fields を UNDynamics terms へ写像する責務を持つ。Solver backend は source kind を知らず、UNDynamics runtime view と評価済み runtime state だけを読む。
VRC PhysBone の Pull / Spring / Momentum / Stiffness / Gravity Falloff / Immobile とそれぞれの curve は sourceParams から UNDynamics の normalized scalar / per-joint samples へ lower する。`integrationType` などの source text は importer 境界で大小文字差を正規化し、solver には `UnaDynamicsIntegrationType` と response term だけを渡す。angle limit curve も同じ per-joint sample 境界で扱い、solver は joint ごとの実効 limit を読む。VRM SpringBone の stiffness は authored rest-pull intent として pull へ mirror する。solver backend は source component を直接読むのではなく、pull / spring-or-momentum / stiffness / gravity / falloff / immobile / drag / limit / collider などの normalized runtime term を読む。数値目標は source component の再現ではなく、自然さ、安定性、調整可能性を公開情報と黒箱観測で確認できる範囲で詰める。non-leaf root の `endpointPosition` は terminal leaf ごとに synthetic endpoint tail として lower する。endpoint が leaf と同一点になり tail 長を作れない degenerate case だけは warning とし、既存 chain を維持する。
VRC PhysBone の Pull / Spring / Momentum / Stiffness は 0-1 normalized slider として保存し、UNPhysics の runtime response へ変換して使う。これは VRM SpringBone の stiffness 由来値を同じ authored intent として統合しつつ、source 固有の内部 solver を模倣しないための境界である。VRM SpringBone の stiffness は source payload / legacy field として `stiffness` に残っていても、UNPhysics lowering では rest response intent として `pull` へだけ使い、局所形状保持 `shape_preservation` へは使わない。`stiffness_samples` が VRM SpringBone 由来として存在する場合も同様に pull sample fallback として扱い、shape sample にはしない。VRC PhysBone の Stiffness とは意味が異なるためである。
VRC PhysBone の Limit Rotation は UNDynamics limit の `limit_rotation` として保持し、Angle / Hinge / Polar limit の中心軸計算に使う。これにより公開 Creator Docs の Limits 節にある Rotation 指定を solver が無視しない。

Collider shape は structured field として扱い、known shape は `sphere` / `capsule` / `plane` と runtime-local variant に限定する。`not_a_sphere` のような substring accident は unknown shape として監査し、solver contact / projection evidence に混ぜない。

Wardrobe hot switch、runtime action、Menu / Parameter candidate、Contacts metadata / opt-in emission diagnostics は v2 初回リリースの physics QA に十分な基盤とする。
